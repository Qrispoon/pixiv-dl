# Pixiv 标签批量下载 CLI —— 前期调研（prior-art）

> 对象：Node.js/Windows 自研 CLI，计划走 refresh_token + app-api 标签搜索 + 客户端收藏数过滤 + 限速下载。
> 日期：2026-11-12。方法：GitHub API / raw 源码、pixiv 官方帮助页、issue 记录，以及在本机经 `http://127.0.0.1:10090` 代理的少量无害探测（未登录、无真实 token）。
> 证据强度：**[A]** 官方文档/权威规范；**[B]** 活跃项目源码或维护者表态；**[C]** 社区 issue / 个人实测；**[D]** 未证实/推测。

## 0. 速览

- 路线可行，且已有高度相似的成熟实现可参照（gallery-dl、Go 版 pixiv-cli）；但 refresh_token 获取、offset 5000 上限、账号级 429 是三个硬边界。
- Node 生态没有可用库（现有 npm 客户端均停更），需要自行封装 HTTP 层。
- 最稳的分页策略不是无限 offset，而是「日期切片 + 本地 id 去重」；gallery-dl 已实现但存在已知漏抓。

gallery-dl pixiv 提取器要点（直接影响我们的设计）：

- 鉴权：`extractor.pixiv.refresh-token`，通过 `oauth.secure.pixiv.net/auth/token` 的 `grant_type=refresh_token` 换 access_token；可用 `gallery-dl oauth:pixiv` 或 gppt 获取 **[B]**（[配置文档](https://github.com/mikf/gallery-dl/blob/master/docs/configuration.rst)）。
- 标签搜索：URL 形如 `/en/tags/<tag>`、`search.php?word=...`；映射到 `search_illust(word, sort, target, start_date, end_date)`，支持 `popular_desc` 与 `scd/ecd` 日期范围 **[B]**（[pixiv.py](https://github.com/mikf/gallery-dl/blob/master/gallery_dl/extractor/pixiv.py)）。
- 收藏数过滤：没有专用参数，但 pixiv 元数据含 `total_bookmarks`，可用通用 `--filter "total_bookmarks > N"` 实现 **[B/C]**。
- 命名：默认目录 `{user[id]} {user[account]}`、文件 `{id}_p{num}.{extension}`，`archive_fmt` 用于去重 **[B]**。
- 仍可用：pixiv 提取器在 2026 年仍有针对性提交，OAuth 流程在 2026-03 的 issue 中仍在工作 **[B]**；但存在个别“Invalid refresh token”未闭环报告（见 §2）。

结论：**没有现成的、活跃的 Node CLI**；gallery-dl / pixiv-cli 是最直接的功能与实现参照系。

## 2. 获取 / 使用 refresh_token 的路径对比

现状（2026）：app-api 的 OAuth 刷新仍是主流，公开的 Android/iOS 客户端凭据仍被社区项目使用。

- 刷新请求：`POST https://oauth.secure.pixiv.net/auth/token`，`client_id=MOBrBDS8blbauoSck0ZfDbtuzpyT`、`client_secret=lsACyCD94FhDUtGTXi3QzcFE2uU1hqtDaKeqrdwj`、`grant_type=refresh_token`、`get_secure_url=1`，附 `X-Client-Time` / `X-Client-Hash`（时间+固定 salt 的 MD5）**[B]**（gallery-dl 源码 [pixiv.py:1134-1194](https://github.com/mikf/gallery-dl/blob/master/gallery_dl/extractor/pixiv.py)；[PixEz oauth_client.dart](https://github.com/Notsfsssf/pixez-flutter/blob/master/lib/network/oauth_client.dart) 使用同一组值）。
- 尚未发现 2025–2026 年“client_id 被整体封禁”的可靠报告；gallery-dl 与 PixEz 源码仍在用同一组值，可视为当前有效（但无官方承诺）**[B/C]**。本轮未能实测 token 端点（执行环境自动拦截了含 client_secret 的请求），故仅源码级佐证。

| 路径 | 步骤 | 成功率/现状 | 主要风险 |
| --- | --- | --- | --- |
| **gallery-dl `oauth:pixiv`** | 命令打印 `https://app-api.pixiv.net/web/v1/login?code_challenge=...&client=pixiv-android` → 浏览器登录 → DevTools Network 抓 `callback?...&code=` → 30 秒内粘贴 code（其提示允许直接粘贴整段 URL）→ 换取并缓存 refresh_token | 2026-03 的 issue 显示流程可用 **[B]**（[#9331](https://github.com/mikf/gallery-dl/issues/9331)） | 需浏览器+手动操作、code 30 秒过期；Windows 需先装 gallery-dl/Python；也有用户粘贴后报 Unsupported URL（[#7229](https://github.com/mikf/gallery-dl/issues/7229)） |
| **gppt v5** | `gppt configure`（账号/密码/TOTP 或 oauth）→ `gppt login`；e2e 方式用无头浏览器自动登录，输出 token JSON | 维护活跃，文档完整 **[B]** | 需要账号密码（部分用户只有第三方登录）；自动化登录可能触发风控/验证码（未证实）；凭据落盘 |
| **手动 gist / 第三方网页工具** | 经典流程：登录页 DevTools 过滤 `callback?`，复制 code 调 `/auth/token`（`grant_type=authorization_code` + PKCE verifier） | 流程与 gallery-dl 相同，pixivpy README 推荐（[ZipFile gist](https://gist.github.com/ZipFile/c9ebedb224406f4f11845ab700124362)）**[C]** | 第三方网页工具会拿到等同账号访问权的 refresh_token，**不可信**；code 同样短命 |
| **Cookie（PHPSESSID）走 web/ajax** | 浏览器登录后导出 cookie → `www.pixiv.net/ajax/*` | 仍可用，gallery-dl 用它处理 sanity 限制、ugoira 原始 zip **[B]** | 不能用于 app-api；Cloudflare 对 web 页面有挑战（本机实测返回 CF 脚本）**[C]**；cookie 易失效 |

已知失效报道（需正视）：

- gallery-dl [#9331](https://github.com/mikf/gallery-dl/issues/9331)（2026-03）：刚完成 oauth 就报 `Invalid refresh token`；作者修复了缓存 token 的 bug（commit 3794e59），但报告者 2026-04-02 更新后仍失败，issue 被关闭、**未确认解决**。可能原因（缓存旧 token、账号侧使 token 失效、多客户端并行登录）均未证实 **[C/D]**。
- 结论：refresh_token 是“一次性拿到、长期使用”的凭证，但**存在被服务端判定失效且原因不透明的风险**，产品必须提供“导入新 token”的兜底，而不能把首次登录当作一劳永逸。

## 3. 限流 / 反爬的社区实证

- **429 的性质**：活跃 Android 客户端 Pixiv-Shaft 的限流设计文档称 429 是「账号级速率限制」，撞限流应整队冷却而非单条退避，并遵守响应中的 `Retry-After`（示例出现 `Retry-After: 86400`），其写操作（收藏/关注）最小间隔设为 **2 秒** **[C]**（[action-queue.md](https://github.com/CeuiLiSA/Pixiv-Shaft/blob/classic/docs/action-queue.md)）。
- **官方无公开配额**：pixiv 未发布 app-api 速率表，所有阈值均为社区经验 **[D]**。
- **gallery-dl 的保守默认**：`sleep-429` 默认 **60 秒**再重试，可配置线性/指数退避；pixiv 不在默认有请求间隔的站点列表中（默认 0 间隔）；源码遇到 `"rate limit"` 错误直接 `wait(300s)` 后重试 **[A/B]**（[configuration.rst](https://github.com/mikf/gallery-dl/blob/master/docs/configuration.rst)、pixiv.py）。实际重度用户会用 `--sleep-429 180` **[C]**（[#8843](https://github.com/mikf/gallery-dl/issues/8843)）。
- **建议值（推导，非硬数据）**：读请求 1–2 秒间隔、**单线程串行**；搜索结果批量抓取时分页与图片下载分开限速；遇 429 读 `Retry-After`，退避起点 60 秒、指数增长。并发 >1 无任何正向证据，风险自负 **[D]**。
- **User-Agent / Referer**：gallery-dl 现行实现给 app-api 请求带 `PixivIOSApp/7.19.1 (iOS 16.7.2; iPhone12,8)`、`App-OS/App-Version`、`Referer: https://app-api.pixiv.net/` **[B]**。本机实测：不带 UA/Referer 的 curl 请求 app-api 未被 Cloudflare 拦截，返回的是 OAuth 错误 JSON（`invalid_request`），说明当前不是硬门槛，但伪装成官方客户端仍是降低风控概率的合理做法 **[C]**。
- **图片域名**：`i.pximg.net` 强制校验 Referer。本机 2026-11-12 实测：无 Referer → **403**；带 `Referer: https://www.pixiv.net/` → 404（错误路径但已过校验）**[C 强]**。下载器必须设置该 Referer，且不能依赖 404/403 区分作品存在性。
- **R-18 与 filter=for_ios**：app-api 的 `filter` 只有 `for_ios` / `for_android` 两个枚举（社区逆向的 [OpenAPI 文档](https://github.com/hanshsieh/pixiv-api-doc/blob/master/api.yaml)，非官方 **[C]**），pixivpy 各接口默认 `for_ios` **[B]**。R-18 是否可见由**账号设置与登录态**决定（官方帮助：未登录、开启隐藏敏感/年龄限制内容、或地区限制时，作品不会出现在列表）**[A]**（[pixiv 帮助](https://www.pixiv.help/hc/zh-tw/articles/42890163268633)）。`filter=for_ios` 本身是否额外过滤 R-18：**未证实**，需实测两种取值；另注意 app-api 返回结果可能少于 web（pixivpy [#277](https://github.com/upbit/pixivpy/issues/277)）**[C]**。
- **offset 上限 5000**：App API 搜索 offset 到 5000 即无法继续，pixivpy 早年已实测（[#69](https://github.com/upbit/pixivpy/issues/69)）**[C]**；gallery-dl 2026 年源码在 `offset >= 5000` 时自动把 `end_date` 提前一天/`start_date` 后移一天继续翻页 **[B]**。该绕过在超大样本上会**漏抓/提前停止**（[#8843](https://github.com/mikf/gallery-dl/issues/8843)，2026-01 至今 open）**[C]**。→ 自研必须自己实现日期切片，并用 id 集合回补。
- **popular_desc**：pixivpy README 注明「popular_desc 为会员的热门排序」**[B]**；PixEz 观察到非会员会弹 “not premium” 但排序仍返回（[#510](https://github.com/Notsfsssf/pixez-flutter/issues/510)）**[C]**。**不要把它作为主路径**，用 `date_desc` 全量抓取后本地按 `total_bookmarks` 排序/过滤更稳。
- **收藏数过滤可行性**：app-api 的 illust 对象含 `total_bookmarks`（pixivpy 模型 **[B]**、社区 api.yaml **[C]**），本地过滤成立；搜索接口本身没有按收藏数过滤的参数（未见证据，**未证实**）。

## 4. 图片下载细节

- **多页原图**：app-api 的 illust 详情含 `meta_pages[].image_urls.original`（多页）与 `meta_single_page.original_image_url`（单页）；gallery-dl 直接取 `original`，并用 `_p{num}` 后缀区分页 **[A/B]**（[api.yaml](https://github.com/hanshsieh/pixiv-api-doc/blob/master/api.yaml)、pixiv.py）。
- **受限作品**：sanity/年龄限制作品可能只返回 `limit_*` 占位 URL，需要登录 cookie 走 `www.pixiv.net/ajax/illust/<id>` 回退；gallery-dl 的报错文案是 “Provide logged-in cookies to access it” **[B]**。→ 只用 refresh_token 可能拿不到这部分原图，需要明确“不支持”或额外提供 cookie 选项。
- **命名与去重**：pixiv id + 页号 + 扩展名是最稳命名（如 `12345678_p0.jpg`）；标题/画师名仅作可选前缀，注意 Windows 非法字符（`\/:*?"<>|`）与长度。去重用 illust id 或 gallery-dl 式 archive DB（`archive_fmt = {id}{suffix}.{extension}`）**[B]**。
- **ugoira（动图）**：app-api `/v1/ugoira/metadata` 返回 `frames[{file, delay}]` 与 `zip_urls`（通常只有 medium=600x600）；gallery-dl 会把 URL 中 `_ugoira600x600` 替换为 `_ugoira1920x1080` 尝试取更高清 zip，或 `ugoira: original` 走 ajax 下载逐帧原图 **[B]**。
- **格式与转换**：官方交付是 **zip（帧 JPG/PNG + 帧延迟表）**；要 GIF/MP4/WebM 需外部 ffmpeg（gallery-dl 的 ugoira 后处理器：默认输出 webm，`mode=auto` 优先 mkvmerge，否则 concat；`image2` 模式明确不支持 Windows/macOS）**[A]**（[configuration.rst ugoira 段](https://github.com/mikf/gallery-dl/blob/master/docs/configuration.rst)）。→ Windows CLI 内置转换只能选 ffmpeg concat（帧延迟不均时时间戳不准），或默认只存 zip/帧 + 提示用户自行转码。
- **网络**：图片域与 API 域不同，代理需同时覆盖 `app-api.pixiv.net`、`oauth.secure.pixiv.net`、`i.pximg.net`；本机 app-api/i.pximg 经 HTTP 代理可通，直连不通 **[C]**。

## 5. 对自研路线的结论与规避建议

**可行性：高，但边界清晰。** refresh_token + app-api（`/v1/search/illust` + `/v1/illust/detail` + `/v1/ugoira/metadata`）+ 本地 `total_bookmarks` 过滤 + 限速下载在技术上完全成立，gallery-dl 与 Go 版 pixiv-cli 已证明该组合可用。真正的风险不在“能不能写”，而在鉴权凭证生命周期、深翻页完整性和账号级限流。

主要风险：

1. **凭证单点**：refresh_token 需浏览器 PKCE 手动获取，且存在不明原因失效报告（#9331）。没有它整个工具不可用。
2. **覆盖率**：offset 5000 上限使“按 tag 抓全量”必须日期切片；gallery-dl 的切片已被报告会漏抓。app-api 结果也可能少于 web（#277）。
3. **限流**：429 为账号级，阈值不公开；批量搜索+下载很容易在中途被冷却，重试逻辑写错会放大封禁时长。
4. **内容边界**：R-18/受限作品受账号设置、地区、登录 cookie 影响；仅 refresh_token 可能拿不到原图或 ugoira 原始 zip。
5. **实现成本**：Node 无活跃库、无官方 API 文档，schema 依据社区 OpenAPI 与逆向（稳定性风险）；web/ajax 路线还有 Cloudflare。

规避建议：

1. **鉴权**：内置 PKCE 登录（本地临时 HTTP 服务接收回调，参考 pixiv-cli 的 loopback + `pixiv://` 方案），同时支持手动导入 refresh_token 作为兜底；token 仅存本地、限制文件权限；刷新失败时提示重新授权，绝不静默重试登录。
2. **分页**：offset 到 ~4500 就切换日期窗口（`start_date`/`end_date` 按 `create_date` 前后推移），维护已抓 id 集合去重；对切片边界做重叠回扫（前后各留 1 页）以补漏。不要假设一次翻页就能抓全。
3. **限速**：默认 1.5–2 秒/请求、单线程；429 时优先读 `Retry-After`，否则 60s 起指数退避；设置全局请求预算/暂停键；给用户暴露 `--delay`、`--max-requests`。
4. **搜索与排序**：只用 `date_desc` 抓取，`total_bookmarks` 本地排序/过滤；不依赖 `popular_desc`（会员限定且结果不完整）；R-18 明确按账号设置返回结果，不做绕过承诺。
5. **下载与格式**：图片请求固定 `Referer: https://www.pixiv.net/` 与 App UA；文件按 `id_p{n}.{ext}` 命名并做存在性去重；ugoira 默认保存 zip + frames 元数据，ffmpeg 转码做成可选外部依赖而非硬依赖；所有 HTTP 请求支持显式代理配置（本机直连不可用已实测）。

> 未证实项汇总：429 精确阈值与封禁时长；`filter=for_ios` 是否过滤 R-18；refresh_token 失效的具体触发条件；app-api 与 web 数据差异的完整范围；官方是否容忍第三方客户端长期使用。
