> 配套文档：[01-可行性报告.md](01-可行性报告.md)（实测证据与风险）。本文是可执行的项目方案：需求、架构、CLI 规格、算法、工程细节、测试与里程碑。

## 1. 目标与非目标

### 1.1 目标（v1）

一个 Windows 上可用的命令行工具：给定一个或多个 Pixiv 标签，把该标签下**收藏数 ≥ 阈值**的作品原图下载到指定文件夹，文件名统一为：

```
{画师}-{作品pid}-{收藏数}.{扩展名}
```

必须满足：

1. 支持多标签、多页作品（`_p0`、`_p1`…）、动图 ugoira（默认转 gif，可切 mp4/zip）。
2. 收藏数门槛可配置，且多页作品只算一次门槛。
3. 断点续跑：中断后重跑不重复下载、不重复扫描（尽力）。
4. 全链路走本机 HTTP 代理（`127.0.0.1:10090` 这类地址），限速保守，遇到 429/5xx 自动退避，不追求速度。
5. 单文件分发/`npm link` 即可运行，**零运行时依赖**（仅动图转码可选依赖 ffmpeg）。
6. **覆盖可核对**：每个日期窗口输出「应有条数 / 已枚举条数 / 补漏条数」，覆盖率不达标时明确告警（实现见 §9.5）。

### 1.2 非目标（v1 明确不做）

- 小说、FANBOX、pixivision、排行榜批量、关注流、「我的收藏」同步。
- 任何写操作（收藏、关注、上传、评论）。
- GUI / 常驻服务 / 定时任务（后续可用 `schtasks` 调用本 CLI）。
- 绕过付费墙、破解 R-18 限制或验证码；R-18 仅按账号自身权限获取。
- 跨设备状态同步、去重库导出。
- 「保证抓全」：Pixiv 搜索有 offset 5000 上限、日期切片有已知漏抓报告（gallery-dl #8843）、app-api 结果可能少于 web（pixivpy #277）。本工具只承诺「尽力抓取 + 可解释的覆盖范围」，不承诺 100% 完整。

## 2. 需求与验收标准

| 编号 | 需求 | 验收方式（可执行） |
| --- | --- | --- |
| R1 | `ptdl doctor` 全绿：代理、四域名、鉴权、图片、ugoira | 退出码 0；输出 JSON 可解析 |
| R2 | `ptdl login` 一次获取 refresh_token 并持久化，后续免登录 | 重启终端后直接下载成功 |
| R3 | 按标签 + 最低收藏数下载，文件名符合模板 | 抽查文件：`360-100412238-11247.png` |
| R4 | 多页作品完整下载，命名带 `_p{n}` | 页数 = `page_count` |
| R5 | 动图下载为 zip（或 gif/mp4） | 文件可解压/播放，帧数 = `frames.length` |
| R6 | 中断后重跑不重复、扫描可续 | 第二次运行 downloaded=0，日志显示从 cursor 继续 |
| R7 | 429 触发后自动退避而非崩溃 | 模拟 429 的 fixture 测试 + 真机观察 |
| R8 | 运行期限速：默认 API 2 秒/请求（单线程）、下载并发 2；429 冷却后重试 | 日志时间戳间隔与 429 重试可验证 |
| R9 | 错误可恢复：失败清单落盘，`ptdl retry` 可重试 | 删除网络后产生失败项，恢复后可重试成功 |
| R10 | Windows 文件名合法（非法字符/保留名/长度） | 单测覆盖 + 真机含特殊字符画师名用例 |
| R11 | 覆盖核对：每窗口输出 应有下界/已枚举/确认缺口/补漏/状态，写入 `coverage.json` | 真机跑一个日窗口，`complete`/`repaired`/`estimated_gap` 判定正确 |
| R12 | 单日 >5000 条的窗口能双向枚举，并能判定是否接上 | coverage-lab 输出 boundaryOk；不接上时明确报告 estimated_gap |

## 3. 技术选型

| 维度 | 选择 | 理由 |
| --- | --- | --- |
| 语言/运行时 | **Node.js ≥ 24（ESM，纯 JS + JSDoc 类型注释）** | 本机已有 Node 26；无 Python；内置 `fetch` 支持 env 代理（已实测）；免编译、免依赖 |
| 依赖 | **零运行时依赖**；`devDependencies` 可选 ESLint | 减少供应链与安装成本；`node:test`、`util.parseArgs`、`node:zlib` 足够 |
| 网络层 | 内置 `fetch` + 自封装 `http.mjs`（超时/重试/日志/代理重入） | 实测可行；统一注入 headers、Referer |
| 代理 | `HTTPS_PROXY`/`HTTP_PROXY` + `--use-env-proxy`；`--proxy` 参数通过「重定位自身进程」注入 | 实测：启动后改 env 无效；SPAWN 方式可靠且零依赖 |
| 鉴权 | App API + OAuth refresh_token（PKCE 获取） | 唯一稳定且字段完整的路线（含 `total_bookmarks`） |
| 收藏过滤 | 默认本地过滤 `total_bookmarks`；Premium 追加服务端 `bookmark_num_min/max` + 本地复核 | 非 Premium 无服务端过滤（见可行性报告 3.3） |
| 状态 | 输出目录下 `.pixivdl/`：`state.jsonl` + `cursors.json` + `failed.jsonl` + `lock` | 追加写、崩溃安全、易人工检查；无需 SQLite 依赖 |
| 动图 | 默认 GIF（用户选择，实测可用）；`--ugoira mp4|zip` 可切；系统 `tar.exe`（Win10+ 自带 libarchive）+ `ffmpeg` | 解 zip 与转码都交给成熟外部工具，缺失时降级并提示 |
| 测试 | `node:test` + 本地 fixture HTTP 服务 | 不依赖真机网络；真机只做 smoke |

**为什么不做成 gallery-dl 的封装**：本机无 Python；且用户要的是「画师-pid-收藏数」的固定命名与最小收藏数语义，自研 CLI 才能把扫描策略、断点、限速按本需求定制。gallery-dl 的实现仅作为参考（已留存源码副本 （本地参考，未随仓库分发））。

**可对照的活跃实现**（详细见 [`docs/06-同类工具调研.md`](06-同类工具调研.md)）：[gallery-dl](https://github.com/mikf/gallery-dl)（Python，功能最全，日期切片/登录流程可参考）与 [pixiv-cli](https://github.com/FlanChanXwO/pixiv-cli)（Go，App API + 浏览器 OAuth + 收藏数过滤，`bookmark_num_min/max` 与 Premium 策略的源码证据来自它）。两者都验证了本方案技术路线；没有活跃的 Node 现成库，自研 HTTP 层是必要成本。

### 4.1 数据流（单标签）

```
login → access_token
  │
  ▼
search(tag, window, offset) ──► 30 条/页 ──► 过滤 total_bookmarks ≥ M
  │                                              │ 通过
  │ offset+30，直到 5000 或 next_url=null         ▼
  │ 命中 5000 → end_date 前移（日期切片）      解析: 画师名/pid/收藏数/页URL
  │                                              │
  ▼                                              ▼
扫描游标持久化                              下载原图(带 Referer) → *.part → rename
                                                 │
                                                 ▼
                                         state.jsonl 记录 + 汇总输出
```

### 4.2 模块职责

| 模块 | 职责 | 关键接口 |
| --- | --- | --- |
| `http.mjs` | 统一请求：UA/Referer 注入、超时、`AbortController`、gzip、日志脱敏 | `getJSON(url, opts)`、`getStream(url, opts)` |
| `auth.mjs` | PKCE 登录、`refresh_token→access_token`、401 自动重取、token 持久化 | `loginInteractive()`、`ensureAccessToken()` |
| `pixiv.mjs` | App API 客户端：搜索、作品详情、ugoira 元数据；错误码映射 | `searchIllust(params)`、`ugoiraMeta(id)` |
| `webapi.mjs` | Web Ajax 路线（匿名 / PHPSESSID）：`pages`/`ugoira_meta` 兜底，以及**覆盖核对与补漏**用的搜索（`scd/ecd` + `p` 深翻页 + `total`） | `pages(id)`、`ugoiraMeta(id)`、`searchArtworks({word,scd,ecd,p})` |
| `coverage.mjs` | 每窗口覆盖核对：Web `total` vs app-api unique pid；差额窗口用 Web 深翻页补 id；生成覆盖报告 | `checkWindow()`、`repairWindow()` |
| `search.mjs` | 日期窗口切片、offset 上限、去重（Set<pid>）、游标读写、调用 coverage | `async* scan({tag,filter,cursor})` |
| `filter.mjs` | 收藏数区间、类型、AI、R-18、可选标签排除 | `match(work) → boolean` |
| `naming.mjs` | 模板渲染、Windows sanitize、长度截断、扩展名推导 | `filename(work, page)` |
| `download.mjs` | 单图/多页/ugoira 下载、并发控制、`.part` 原子写、失败记录 | `downloadWork(work)` |
| `state.mjs` | JSONL 追加、读取索引、失败清单、lock、compaction、`coverage.json` | `isDone(pid)`、`markDone()`、`addFailed()` |
| `ratelimit.mjs` | API 串行 + 令牌桶、下载并发信号量、指数退避 | `apiSlot()`、`downloadSlot()` |
| `report.mjs` | 进度行、汇总表、覆盖报告、`--json`、退出码 | `progress()`、`summary()` |

## 6. CLI 规格

### 6.1 命令

| 命令 | 作用 |
| --- | --- |
| `ptdl login` | PKCE 浏览器登录，保存 refresh_token；`--token <t>` 可直接粘贴已有 token |
| `ptdl doctor` | 环境/代理/鉴权/接口能力自检（探针的正式版），`--json` |
| `ptdl download <tag...>` | 主命令：搜索 → 过滤 → 下载 |
| `ptdl retry` | 重试 `failed.jsonl` 中的条目 |
| `ptdl state` | 统计已下载/失败/游标；`--clean` 清理游标 |

### 6.2 `download` 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-o, --out <dir>` | `./downloads` | 输出根目录 |
| `-m, --min-bookmarks <n>` | `0` | 收藏数下限（含） |
| `--max-bookmarks <n>` | 无 | 收藏数上限（含），便于反向筛选 |
| `-n, --limit <n>` | 无 | 本次最多下载作品数（不含页数） |
| `--max-pages <n>` | `200` | 每标签每窗口最多搜索页数，防失控 |
| `--since <YYYY-MM-DD>` | 无 | 起始发布日期 |
| `--until <YYYY-MM-DD>` | 今天 | 截止发布日期 |
| `--sort <date\|popular>` | `date` | `popular` 仅 Premium，显著加速 |
| `--exact` | 关 | 标签精确匹配（`exact_match_for_tags`） |
| `--and` | 关 | 多标签合并成一次搜索（默认逐个搜索后按 pid 合并） |
| `--type <illust\|manga\|all>` | `all` | 作品类型 |
| `--r18 <exclude\|include\|only>` | `exclude` | `filter=for_ios` / 空 / 客户端 `x_restrict>0` |
| `--ai <exclude\|include\|only>` | `include` | 是否包含 AI 作品（`search_ai_type`） |
| `--ugoira <gif\|mp4\|zip\|skip>` | `gif` | 动图交付形式；gif/mp4 需 ffmpeg（本机已装） |
| `--ugoira-width <px>` | `540` | GIF/MP4 输出宽度（480–1080；原图 1920 时按比例缩放） |
| `--keep-ugoira-zip` | 关 | 转码后保留原始 zip |
| `--name <template>` | `{artist}-{id}-{bookmarks}` | 文件名模板 |
| `--by-tag` | 关 | 按标签建子目录（默认平铺） |
| `--jobs <n>` | `2` | 下载并发 |
| `--delay <秒>` | `2` | App API 请求最小间隔（单线程）。实测 0.5s 间隔约 183 次请求触发 429，故默认 2s |
| `--max-wait <秒>` | `600` | 单次退避上限；`Retry-After` 超过该值则直接中止（避免盲睡 24h） |
| `--server-bookmark-filter <auto\|on\|off>` | `auto` | 收藏数是否下发服务端参数：`auto`=Premium 时启用；始终本地复核 |
| `--coverage-check <strict\|best-effort\|off>` | `best-effort` | `strict`：差额窗口必须补漏成功，否则退出码 5；`best-effort`：补漏失败仅告警；`off`：跳过 Web 核对（省请求） |
| `--proxy <url>` | env | HTTP(S) 代理地址；`--no-proxy` 强制直连 |
| `--retries <n>` | `5` | 单请求最大重试次数 |
| `--timeout <s>` | `30` | 单请求超时 |
| `--dry-run` | 关 | 只打印将下载的清单，不写文件 |
| `--force` | 关 | 忽略状态强制重下 |
| `--no-resume` | 关 | 忽略扫描游标，从头扫描 |
| `--json` | 关 | 结构化输出（每行一个事件 + 最终 summary） |
| `-v, --verbose` | 关 | 打印 HTTP 级日志（token 脱敏） |

### 6.3 示例

```powershell
# 首次登录（浏览器打开 Pixiv 登录页；按提示粘贴 callback 里的 code）
ptdl login

# 自检
ptdl doctor

# 下载「初音ミク」中收藏 ≥ 1000 的作品到 D:\pixiv\miku
ptdl download 初音ミク -m 1000 -o "D:\pixiv\miku" --since 2024-01-01

# 多个标签（默认逐个搜索、按 pid 去重合并）
ptdl download 初音ミク アークナイツ -m 5000 -o "D:\pixiv\mix"

# 只看前 2 页、最多 20 件、动图转 gif、dry-run 预览
ptdl download 女の子 -m 10000 --max-pages 2 --limit 20 --ugoira gif --dry-run
```

### 6.4 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部成功（可能部分作品被过滤，属正常） |
| 1 | 运行完成但有失败项（见 `failed.jsonl`） |
| 2 | 参数/配置错误 |
| 3 | 鉴权失败（refresh_token 无效/过期，需重新 login） |
| 4 | 网络/代理不可用 |
| 5 | 触发风控（429/403 且退避无解），建议暂停 |
| 130 | Ctrl+C 中断（状态已落盘，可续跑） |

## 7. 配置与凭据

### 7.1 配置优先级

`CLI 参数 > 环境变量 > 项目配置 ./ptdl.config.json > 用户配置 %APPDATA%\pixiv-tag-dl\config.json > 内置默认`

### 7.2 配置示例

```json
{
  "refresh_token": "xxxx",
  "proxy": "http://127.0.0.1:10090",
  "out": "D:/pixiv",
  "min_bookmarks": 1000,
  "name": "{artist}-{id}-{bookmarks}",
  "jobs": 2,
  "api_rate": 1,
  "ugoira": "gif",
  "r18": "exclude",
  "ai": "include"
}
```

- `refresh_token` 明文保存（个人工具），文件权限尽量收紧；也可用环境变量 `PIXDL_REFRESH_TOKEN` 完全避免落盘。
- 代理优先级：`--proxy` > `PIXDL_PROXY` > 配置 `proxy` > `HTTPS_PROXY/HTTP_PROXY`。
- 首次运行 `ptdl download` 若无配置，自动引导到 `ptdl login`。

## 8. 鉴权流程（一次性 + 自动续期）

### 8.1 `ptdl login`（PKCE，参考 gallery-dl 现成实现）

> 前置工具已经可用：[`scripts/login.mjs`](../scripts/login.mjs) 就是该流程的零依赖实现（浏览器登录 → 粘贴回调 code → 保存 `.secrets/pixiv-refresh-token.txt`）；`ptdl login` 只是把它并入主 CLI 并增加配置写入。验证阶段可直接用它拿 token。

1. 生成 `code_verifier`（32 字符随机）+ `code_challenge = base64url(sha256(verifier))`。
2. 打开浏览器：`https://app-api.pixiv.net/web/v1/login?code_challenge=…&code_challenge_method=S256&client=pixiv-android`
   （实测 302 → `accounts.pixiv.net/login`，说明流程存活）。
3. 终端提示（借鉴 gallery-dl 文案）：
   ```
   1) 先在浏览器按 F12 打开开发者工具 → Network 面板
   2) 完成登录
   3) 选中最后一条 callback?state=… 请求
   4) 复制其中的 code 值（或整条 URL）粘贴到终端
   注意：code 30 秒后过期，请提前打开 Network 面板
   ```
4. 读取 `code`（允许粘贴整条 URL，用 `rpartition("=")` 方式取最后一段）。
5. `POST https://oauth.secure.pixiv.net/auth/token`
   `grant_type=authorization_code`、`code`、`code_verifier`、`client_id`、`client_secret`、
   `redirect_uri=https://app-api.pixiv.net/web/v1/users/auth/pixiv/callback`、`include_policy=true`，
   头：`User-Agent: PixivAndroidApp/5.0.234 (Android 11; Pixel 5)`。
6. 成功响应含 `refresh_token` 与 `user`（`id`、`name`、`is_premium`）→ 保存并打印欢迎信息；失败时提示「code 过期，重试」或「token 无效」。

### 8.2 运行期

- 每次进程启动：用 refresh_token 换 access_token（1 次请求），401 时自动重试一次。
- access_token 只在内存中；refresh_token 失效 → 退出码 3，提示 `ptdl login`。
- 备用：`ptdl login --token <refresh_token>` 适合用户从其他工具/旧配置迁移，或 PKCE 流程失效时的降级。

### 8.3 备选鉴权路线（v1 不实现，仅保留设计）

| 路线 | 说明 | 触发条件 |
| --- | --- | --- |
| Web Cookie（PHPSESSID） | 用户浏览器登录后复制 cookie，走 `www.pixiv.net/ajax/*`；搜索列表无收藏数，需逐作品补详情 | app-api 或 PKCE 全面失效 |
| 匿名 Web Ajax | 无需任何凭据；60 条/页，收藏数逐作品补请求 | 临时应急/只下安全内容 |

## 9. 搜索、分页与过滤算法

### 9.1 核心难点

1. App API 搜索 `offset` 上限 5000（每页 30 → 166 页/窗口）；
2. 无服务端收藏数过滤（非 Premium），只能本地过滤；
3. 大标签（62 万作品）必须避免「无脑翻到底」。

### 9.2 扫描伪代码

核心原则：**永远不要相信「翻到 next_url 为空 = 抓全」**。把扫描范围按单日为单位逐步收窄，只有当某一天自身超过 5000 条时才触发双向枚举；每页写游标、每窗口写 coverage 记录。

```
scan(tag, opts, cursor):
  window = { start: opts.since, end: opts.until }
  if cursor 存在且 !opts.noResume:
      window = cursor.window; offset = cursor.offset; seen = state 中的 pid 集合
  while window.start <= window.end:
      offset = window.start == cursor.window.start ? cursor.offset : 0
      overflow = false
      while true:
          resp = appapi.search(word=tag, start_date=window.start, end_date=window.end,
                             offset=offset, sort='date_desc', filter=opts.filter,
                             bookmark_num_min=opts.serverBookmarkMin)   // 仅 Premium
          for w in resp.illusts:
              if w.id in seen: continue
              seen.add(w.id)
              if filter.match(w): yield w
          offset += 30
          saveCursor(tag, window, offset)            // 每页持久化，崩溃可续
          if not resp.next_url: break                 // 窗口内正常结束
          if offset >= 4500:                          // 留 2 页余量，窗口太大
              overflow = true
              lastDate = date(resp.illusts[-1].create_date)
              if window.start == lastDate:            // 窗口已收窄到单个自然日且仍触顶
                  ids = appapi.scanDay(asc, lastDate)  // date_asc 取另一端的 5000 条
                  对 ids - seen 逐个 illustDetail → filter → yield   // L1a
                  coverage.mark(window, expected: web.total(day), collected: |seen|, repaired: |ids差|)
              window.end = lastDate                    // 日期切片：排除更新的一半，保留 lastDate 当天
              break                                    // 重新开窗，seen 去重保证不丢
          if 本标签页数 >= opts.max_pages: return      // 防失控，游标保留
      coverage.record(window, expected: web.total(window), collected: |seen|)   // L1b 核对
```

> 说明：
> 1. `window.end = lastDate`（含当日）+ `seen` 去重，等价于「重叠一整天」，但**不依赖日期字符串比较**，不会重现 gallery-dl #8843 的边界跳过问题。
> 2. 触发阈值取 **4500** 而非 5000，为 `next_url` 与最后一页留余量；窗口逐步收窄，正常情况下很快缩到单日。
> 3. 单日仍触顶 → 双向枚举（`date_desc` 最新 5000 + `date_asc` 最旧 5000），并用边界时间戳判定是否接上；接不上（单日可见 > 约 10000，实测 2025-01-01 即如此）时报告「部分覆盖」，非 Premium 无法补齐。
> 4. 封面/收藏数等字段来自搜索结果，补漏的 id 才需要逐件 `illust/detail`；`web.total` 仅作核对下界（匿名过滤 R-18）。
> 5. 仍不承诺 100%：app-api 索引本身可能与 web 不同（pixivpy #277），这部分只能记录无法修复。

### 9.3 过滤规则（`filter.mjs`）

| 规则 | 条件 |
| --- | --- |
| 收藏数 | `min_bookmarks ≤ total_bookmarks ≤ max_bookmarks` |
| 类型 | `type ∈ {illust, manga}`（ugoira 的 `type` 也是 illust，按 `illustType`/`page_count` 判断） |
| AI | `--ai exclude` → `illust_ai_type===2` 排除；`only` 反之 |
| R-18 | `--r18 exclude` 用 `filter=for_ios` 请求 + 客户端 `x_restrict===0` 双保险；`include` 请求不过滤；`only` 客户端 `x_restrict>0` |
| 去重 | 全局 `Set<pid>`（跨标签、跨运行由 state 提供） |

### 9.4 Premium 加速（可选，检测到 `is_premium` 才启用）

1. **服务端收藏过滤**：搜索请求附带 `bookmark_num_min = max(1, 用户阈值)`、必要时 `bookmark_num_max`（参数名见 pixiv-cli `internal/pixiv/api/routes.go`）。服务端过滤可把「扫描全量」变成「只返回达标候选」，大幅减少请求数；**它同时是绕开覆盖上限的最优解**（不依赖枚举全部作品）。因参数属于逆向接口，**拿到结果后仍本地复核 `total_bookmarks`**。
2. **热门排序早停**：`sort=popular_desc` 返回按收藏降序（官方 Premium 权益）；当最近一页全部低于阈值时可提前结束扫描，扫描量 ≈「达标作品数/30 + 1 页」。
3. **实测（非 Premium 账号，2026-11-14）**：`bookmark_num_min=5000` 被静默忽略；`sort=popular_desc` 退化为时间排序（首屏 `total_bookmarks` 全 0）。因此这两项必须**检测到 `is_premium=true` 才启用**，否则走本地过滤 + `date_desc`。
4. 注意：社区有「非会员传服务端参数也不报错、但结果不完整」的观察（PixEz #510 类似情况），因此不能把服务端过滤当作唯一正确性来源。

### 9.5 覆盖核对与补漏（`coverage.mjs`）

日期切片必然存在边界误差（见可行性报告 3.8）；本模块把「未知的漏抓」变成「可测量的差额」，并对**能定位到 id 的差额**做补漏。核心思路是**先把扫描粒度收窄到「单个自然日」**——只有当某一天自身超过 5000 条时，offset 上限才真正成为不可绕过的墙。

```
对每个单日窗口 D：
  # 1) 枚举
  desc = appapi.scanDay(desc, D)                       # 最多约 5000 条
  overflow  = 在 offset≈5000 处被截断
  if overflow:
      asc = appapi.scanDay(asc, D)                     # 反向再取 5000 条（L1a）
      collected |= asc
      # 关键：用边界时间戳判断两段是否接上（实测必须做）
      boundaryOk = parse(asc.lastDate) >= parse(desc.lastDate)
      if !boundaryOk:
          status = estimated_gap                       # 中间有空洞，非 Premium 无法补齐
  overflowHandled = true

  # 2) 核对（Web，只读第 1 页的 total；仅作下界参考）
  expectedLower = webapi.total({word, s_mode, scd:D, ecd:D})
  gap = expectedLower - |collected|

  # 3) 有限补漏（只有能定位 id 时才有意义）
  if gap > tolerance(默认 max(30, expectedLower*1%)):
      webIds   = webapi.samplePages(D, 1..10)           # 匿名约 600 条
      confirmed = webIds - collected
      for pid in confirmed:
          meta = appapi.illustDetail(pid)               # 失败则 webapi.illust(pid) 兜底
          走 filter → 下载；成功计入 recovered
  写入 coverage.json：{tag, day, expectedLower, collected, overflow, boundaryOk, confirmedMissing, recovered, status}
```

设计要点：

- **双向枚举的真实上限是「2×5000」，且必须验证是否接上**：desc 拿「最新 5000 条」、asc 拿「最旧 5000 条」。实测 `オリジナル` 2025-01-01：desc 5,010 + asc 5,009、重叠 0、并集 10,019，但 asc 最新一条（08:03）比 desc 最旧一条（14:36）早 6.5 小时 → **并集不完整**。原因是登录后可见集合包含 R-18，单日实际 >10,019。因此：
  - `asc.lastDate >= desc.lastDate`（时间戳比较）是「接上」的判定条件；
  - 接不上时，非 Premium 账号无法继续枚举，只能报告 `estimated_gap`；
  - Premium 的 `bookmark_num_min`（服务端收藏过滤）或 `popular_desc`（热门排序）可从根上绕开这个限制。
- **「能定位 id 的缺口」才谈得上补漏**：Web 匿名深翻页被钳制在约 600 条/查询，所以从 Web 最多能拿到约 600 个候选 id 做差分；超过这个量级的缺口，Web 也给不出 id。
  - 能定位 → 用 id 走 app-api `illust/detail` 补全元数据（收藏数/画师/多页 URL），失败再退 Web `ajax/illust/{id}` + `pages`，然后正常过滤下载。
  - 不能定位（`estimated_gap`）→ 无法凭空得到 id，只能报告「推测缺口 N 条」及其原因（>10000/日、索引差异、R-18 可见性）。
- **Web 的角色是核对 + 有限差分，不是枚举主力**：`scd/ecd + total` 用于下界核对；`p=1..10` 用于最多 600 条的 id 差分。登录态（PHPSESSID）是否放宽深翻页未验证，若放宽可显著扩大可定位缺口范围。
- **`s_mode` 必须与主搜索一致**：`--exact` → `s_tag_full`，默认 → `s_tag`；`--and` 的多词合并也要一致，否则 `expected` 基准不可比。
- **R-18 的基准问题**：匿名 Web 搜索实测样本 `xRestrict` 全 0，而登录后的 app-api 结果同时出现 `x_restrict=0/1` → `total` 只是**下界**，不能当等号；`--r18 include/only` 时核对需带 PHPSESSID cookie，否则自动降级为 `unverifiable` 并在报告注明。
- **容差**：Web 与 app-api 索引本身有差异（pixivpy #277），`expected` 只作基准；`--coverage-check strict` 时才把差额视为失败（退出码 5），`best-effort` 仅告警。
- **成本**：核对每窗口 1 次 Web 请求；补漏只发生在 gap 窗口（≤10 次 Web 采样 + 每件 1 次详情）；`--coverage-check off` 可全部跳过。
- **覆盖率状态**：`complete`（collected ≥ expectedLower） / `repaired`（确认缺口已补并下载） / `estimated_gap`（有推测缺口、无法定位 id） / `unverifiable`（无 cookie 或基准不可比）。
- **无法补全**：单日 >10000 条、索引/permission 差异、以及「已定位 id 但作品已删除/私有化」——后者的下载会进 `failed.jsonl`，不是覆盖问题而是可用性问题。

## 10. 下载器设计

### 10.1 命名

- 默认模板：`{artist}-{id}-{bookmarks}`；单页扩展名取 URL 后缀（`.jpg/.png/.gif`）。
- 多页：`{artist}-{id}-{bookmarks}_p0.png`、`_p1.png`…（与 Pixiv 原始命名习惯一致）。
- 动图：`..._ugoira.zip` / `.gif` / `.mp4`。
- `{artist}` 取 `user.name`（显示名），可选 `{account}`（账号名）、`{artist_id}`。
- `sanitize`：替换 `\ / : * ? " < > |` 与控制字符为 `_`；去掉首尾空格与结尾 `.`；处理 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1-9`、`LPT1-9`）；basename 截断到 120 字符（画师名截 60）；超长路径时自动前缀 `\\?\` 或提示改短输出目录。
- 收藏数会随时间变化：默认以「下载时的快照」命名；重跑靠 pid 状态去重，不会因收藏数变大而重下（`--force` 除外）。

### 10.2 解析图片地址

优先用搜索结果自带的 `meta_pages[].image_urls.original`（一次搜索即得，无需额外请求）；`meta_single_page.original_image_url` 为单页。缺失时（老响应/Web 路线）回退 `/ajax/illust/{id}/pages`。

### 10.3 下载流程

```
for each work:
  if state.isDone(pid) and not force: skip
  for each page url:
      GET url  → 写入 `${final}.part` → 校验 content-type 与 content-length → rename
  失败策略：
      404/410 → 标记 deleted，跳过
      403 (limit_sanity_level) → 标记 restricted，跳过并提示
      429 → 读取 Retry-After，否则退避 60s/300s，重试
      5xx/网络 → 指数退避（1s,2s,4s,8s,16s），超过 retries → failed.jsonl
  成功后：state.markDone(pid, files)  ← 单作品全部页成功后才标记完成
```

- 并发：作品级并发 `--jobs 2`；同一作品多页串行（顺序写）。
- 原子性：`.part` + rename；退出时清理 `.part`。
- 已存在同名文件且大小一致 → 视为已下载（修复状态丢失场景）。

### 10.4 动图 ugoira

1. `ugoira_meta` 取 `frames`（`file`+`delay`）与 `originalSrc` zip；
2. `--ugoira zip`：下载 zip 即完成（不转码）；默认是 gif；
3. `--ugoira gif|mp4`：系统 `tar.exe` 解 zip 到临时目录 → 按 `frames[].delay` 生成 concat 清单 → ffmpeg 两遍（GIF 用 `palettegen`+`paletteuse`；MP4 用 libx264）→ 清理临时目录；
4. 帧顺序/延迟以 `frames` 为准，不用文件名猜；
5. 检测不到 `tar`/`ffmpeg` 时打印提示并降级为 zip；`--keep-ugoira-zip` 可同时保留原 zip。

实测命令模板（2026-11-14，ffmpeg 9.0.2 + bsdtar 3.8.9，100 帧 40/50ms）：

```text
# 1) 解包
tar -xf 151837674.zip -C frames
# 2) 生成 frames/list.txt（每帧两行：file 'frames/000000.jpg' / duration 0.04；末帧重复一次）
# 3) 调色板
ffmpeg -f concat -safe 0 -i frames/list.txt -vf "scale=540:-1:flags=lanczos,palettegen=stats_mode=diff" -y palette.png
# 4) GIF（保留每帧延迟）
ffmpeg -f concat -safe 0 -i frames/list.txt -i palette.png -lavfi "scale=540:-1:flags=lanczos[x];[x][1:v]paletteuse=dither=sierra2_4a:diff_mode=rectangle" -loop 0 -y 151837674.gif
```

- 实测：540×304 GIF **4.02 MB**（100 帧 / 4.2s，延迟正确）；1080p GIF 4.27 MB（本例画面简单）；同源 540 宽 MP4 **326 KB**。
- 命名：`{artist}-{id}-{bookmarks}_ugoira.gif` / `.mp4` / `.zip`。
- 注意：GIF 只有 256 色，复杂画面会出色带、体积也可能很大；默认宽度 540（`--ugoira-width` 可调 480–1080），画质敏感建议 `--ugoira mp4`。

## 11. 限速、重试与错误分类

### 11.1 速率默认值（保守）

| 通道 | 默认 | 说明 |
| --- | --- | --- |
| App API 搜索 | **2s/请求**，单线程 | 实测 0.5s 间隔下约 183 次请求触发 429；2s 未再触发；429 为账号级，宁可慢 |
| 图片下载 | 并发 2，单请求间 200–500ms 抖动 | 大文件不额外限速 |
| 429 冷却 | 实测响应**无** `Retry-After` 头；默认冷却 65s 后重试同一页 | 连续 429 指数加长（65→130→260s）；超过 `--max-wait(600s)` 中止 |
| 429 连续 3 次 | 暂停 10 分钟并提示 | 用户可 Ctrl+C 续跑 |

### 11.2 错误分类（`errors.mjs`）

`AUTH`（需重新登录）、`CONFIG`、`NETWORK/PROXY`、`RATE_LIMIT`、`HTTP_4XX`、`NOT_FOUND`、`RESTRICTED`、`WEB_REPAIR`（覆盖补漏失败）、`IO`、`PARSE`。每类决定：重试/跳过/中止/退出码。所有错误写入 `failed.jsonl`（附 `stage`、`http_status`、`url`、`message`），便于 `ptdl retry`。

## 12. 状态、锁与续跑

输出目录结构：

```
<out>/
├─ 360-100412238-11247.png
├─ 360-100412238-11247_p1.png
├─ 151738238_ugoira.zip
```

## 13. 输出、日志与可观测性

- TTY 下进度行：`[2/5 初音ミク] 扫描 12 页 | 命中 34 | 下载 18 | 跳过 9 | 失败 1 | 2s/req`。
- 结束时汇总表：标签、扫描页数、命中数、下载作品/文件/字节、失败数、耗时、输出目录、**覆盖报告（每窗口 expectedLower/collected/confirmedMissing/recovered/status）**；`estimated_gap` 的窗口单独列出，提示原因（>10000/日、R-18 可见性、索引差异）。
- `--json`：每行一个 NDJSON 事件（`scan`/`hit`/`download`/`skip`/`error`/`summary`），便于脚本消费。
- `-v`：HTTP 方法/URL/状态/耗时（`Authorization`、`refresh_token` 打码）。
- 所有写操作前打印将创建的绝对路径（`--dry-run` 时只打印）。

## 17. 风险与缓解（摘要，详见可行性报告第 5 节）

1. **App 凭据/接口变更**：登录失败文案明确；凭据可配置覆盖；关注 pixivpy/gallery-dl 上游动态；`doctor` 一键定位是「网络/凭据/接口」哪层坏了。
2. **refresh_token 无故失效**（gallery-dl #9331）：登录/导入 token 两种入口并存；失败即退出码 3 并提示重新授权，不做静默重登录。
3. **限流风控**：默认 1.5s/请求、单线程、下载并发 2、指数退避；429 为账号级，`Retry-After` 过大时直接中止；分步、可续跑，避免一次跑完巨量。
4. **大标签扫描成本**：默认限制 `--max-pages 200`；推广 `--since`；Premium 用户启用服务端收藏过滤 + `--sort popular`；文档给「62 万作品 ≈ 2 万请求 ≈ 11 小时（2s/req）」的量级说明。
5. **收藏数变化**：按 pid 状态去重；文档说明「重跑不重下」；`--force` 时才按新快照重下。
6. **覆盖率无法保证**：offset 5000 + 日期切片漏抓（#8843）+ app-api 索引差异（#277）叠加；L0 重叠回扫/去重；L1a 超限日 desc+asc 双向枚举 + 边界时间戳判定；L1b Web `total` 下界核对；单日可见 >10,000（实测 `オリジナル` 2025-01-01 并集 10,019 仍缺 6.5h）时如实报告「部分覆盖」，非 Premium 不承诺 100%。
7. **Cloudflare 拦截 Web 兜底路线**：主路线走 app-api 不经过 Cloudflare；Web 兜底补齐浏览器头（实测有效）。

## 18. 需要你确认的默认项（不影响开工，可后改）

| 项 | 当前默认 | 备选 |
| --- | --- | --- |
| 多标签语义 | 逐个搜索、按 pid 合并（OR） | `--and` 合并为一次查询 |
| 画师名 | `user.name` 显示名 | `user.account` 账号名 / 两者都要 |
| 默认收藏门槛 | `0`（不筛） | 建议日常用 500/1000 |
| 动图默认格式 | **gif（已实现，540 宽）** | mp4（326 KB，画质更好）/ zip（原始无损） |
| 输出结构 | 平铺 | `--by-tag` 按标签建子目录 |
| 目标标签规模 | 中小标签（<5000 作品）优先用默认参数 | 大标签请给 `--since` 或 Premium `--sort popular` |
| 运行节奏 | `--delay 2`（单线程、避免账号级 429） | 可调 1–3s；实测 <1s 易触发 429 |
| 覆盖核对 | `--coverage-check best-effort` | `strict` 更严格但慢；`off` 最快 |

> 另有两项「取决于你的账号」的默认：是否 Premium（决定服务端收藏过滤/热门排序是否生效）、是否需要 R-18（决定 `--r18` 默认值）。这两项目前按「非 Premium、排除 R-18」保守处理，登录后 `ptdl doctor` 会打印实际身份，可随时改配置。
